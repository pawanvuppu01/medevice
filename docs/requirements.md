# Medevice — Requirements & Acceptance Criteria

## Purpose
Deliver a large-scale, enterprise-grade website for Medevice covering marketing pages, client portals, admin dashboards, realtime insights, training and project management, and an AI assistant. Provide full-stack implementation (Next.js app, API, DB via Prisma/MySQL), CI/CD, Dockerized local/dev environment, and documentation.

## Scope (Initial MVP)
- Public marketing site: Home, About, Services, Projects, Case Studies, Careers, Contact, Resources, Blog
- Client Portal: Client list, client details, projects, messages, files
- Admin Dashboard: User management, projects, clients, messages, logs, realtime insights
- Training Module: Trainings list, sessions, signups, materials
- AI Assistant: Chat assistant page for internal/admin users
- Authentication: Email/password + role-based access (admin, staff, client)
- Realtime: Live messages, active users, system metrics on admin dashboard
- Data persistence: MySQL via Prisma ORM, seed data for testing
- CI/CD: GitHub Actions for lint/test/build, Docker image build, and deploy steps

## Primary User Roles
- Admin: full access to admin area, user management, metrics
- Staff: manage clients/projects/trainings, view limited insights
- Client: view own projects, messages, files, request trainings
- Guest: view marketing pages, contact form

## Functional Requirements
- Authentication & RBAC with session management
- CRUD APIs for Users, Clients, Projects, Messages, Trainings, Files, Notifications
- File uploads (S3-compatible or local via Docker volume)
- Realtime channel for messages and admin metrics (Socket.IO or Pusher)
- Search & filtering for projects and clients
- Form validation and server-side validation for inputs
- Pagination for lists

## Non-functional Requirements
- Performance: Server-side rendering for marketing pages; Admin dashboard uses CSR where appropriate; target 200ms p95 API response for common endpoints in dev.
- Security: Protect admin routes, input sanitization, secure cookie flags, rate limiting for public endpoints, store secrets in env vars.
- Scalability: Stateless app (in containers) and separate DB; realtime via managed service or horizontally-scalable socket server.
- Observability: Basic logs, request tracing (console logs + structured format), and realtime metrics on dashboard.

## Data Model (high level)
- User (id, name, email, role, hashedPassword, createdAt)
- Client (id, name, contactInfo, projects...)
- Project (id, clientId, ownerId, status, description, startDate, endDate)
- Message (id, projectId|clientId, senderId, body, createdAt)
- Training (id, title, description, sessions...)
- File (id, ownerId, projectId, path, mimeType)
- Notification / Log (id, type, payload, createdAt)

## Realtime Insights (Admin Dashboard)
- Active users (last 5/15/60 minutes)
- Recent messages stream (live feed)
- System events/logs (errors/warnings)
- Simple KPI tiles: total clients, active projects, open trainings

## Acceptance Criteria (per feature)
- Marketing pages render without errors and match supplied content placeholders.
- Auth: Users can sign up (if allowed), login, logout; protected routes redirect unauthenticated to login.
- RBAC: Admin-only pages return 403 for non-admin users.
- CRUD APIs respond with appropriate status codes and validation errors.
- File uploads save to configured storage and are retrievable via signed URL or protected route.
- Realtime: New messages appear to other connected users within 2s in local dev environment.
- CI: PRs trigger lint and tests; failing tests block merge.
